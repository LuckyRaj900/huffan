    Scaling with input size

    Encoding and decoding should grow in proportion to the text length, O(n). This test compresses English text from 10 KB up to 500 KB and records the time.

    How Huffman coding works

    Fixed-width encodings spend 8 bits on every character. Huffman coding gives frequent characters short codes and rare characters long ones, so the average drops. No code is the beginning of another code (a prefix-free code), so the decoder never needs separators.

    The algorithm

    1. Count frequencies. One pass over the text builds a table of character counts.
    2. Make one leaf per character and put all leaves in a min-heap keyed by frequency.
    3. Merge greedily. Remove the two lowest-frequency nodes, join them under a new parent whose frequency is the sum, and push the parent back. Repeat until one node, the root, remains.
    4. Read the codes. Walk from the root to each leaf. A left edge writes 0, a right edge writes 1.
    5. Encode by replacing each character with its code. Decode by walking the tree one bit at a time and restarting at the root after each leaf.
    HUFFMAN(freq):                       # freq[c] = count of character c
    Q = min-heap of leaf(c, freq[c]) for every c
    while |Q| > 1:
        a = EXTRACT-MIN(Q)               # greedy choice: the two rarest nodes
        b = EXTRACT-MIN(Q)
        INSERT(Q, node(freq = a.freq + b.freq, left = a, right = b))
    return EXTRACT-MIN(Q)                # root of the Huffman tree

    Complexity

    Let n be the number of characters and k the number of distinct characters.

    StageTimeWhy
    Frequency countO(n)one pass over the text
    Build the treeO(k log k)k - 1 merges, each with heap operations costing O(log k)
    Generate codesO(k)one traversal of a tree with 2k - 1 nodes
    EncodeO(n)one table lookup per character
    DecodeO(total bits)one edge followed per bit, about n times the average code length

    Why the greedy choice is correct

    Greedy choice property. Some optimal tree has the two rarest characters as sibling leaves at the deepest level: swapping a rare character into a deeper spot never increases the total cost. Optimal substructure. After merging those two into one node, the rest is a smaller instance of the same problem, and an optimal solution to it extends to an optimal solution of the original.

    Huffman coding is optimal among prefix codes that code one character at a time. Its average code length L satisfies H ≤ L < H + 1, where H is the Shannon entropy of the text. The Analysis view of a compression result shows both numbers.

    What counts as compressed size

    The decoder needs the tree, so it is stored in the file. The reported compressed size is the full .huff file: header plus encoded data. Very short texts can therefore come out larger than the original.

    Evaluation parameters

    Original size is the UTF-8 byte length of the input. Compressed size is the byte length of the .huff file. Compression ratio is original / compressed, so 2 : 1 means half the size. Space saved is 1 - compressed / original. Encoding time covers frequency count, tree, codes, bit encoding and file packing. Decoding time covers header parsing, tree rebuild and bit decoding. Times are medians over the chosen number of runs.
